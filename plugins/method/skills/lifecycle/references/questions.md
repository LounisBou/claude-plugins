# The question

In this shape:

```
**Question i of N**
_Subject_ : <a few words>
_Context_ : <two to six sentences: the stake, what is known>
_Question_ : <one sentence ending in a question mark>
_Choices_ :
- **A** : <the choice> — cost: <…> — gain: <…>
- **B** : <the choice> — cost: <…> — gain: <…>
_Free answer_ : <or answer in your own words>
_Recommendation_ : A — <why it beats the others>
```

- Two to five choices, lettered A to E, each a materially different piece of work, never
  shades of one option.
- The free answer is always open and never opens on a lone letter.
- The recommendation argues its letter against the others; a bare letter is none.
- Name every item, in the context and each choice, in plain words (what breaks, for whom,
  what it costs him) and by its pull request with the repository name. A tracking-table row
  number may follow in parentheses, never alone.
- A host dialog, only for a session nobody waits on (`SKILL.md`): options, the recommended
  first and marked, « Other » for the free answer.
- The answer is recorded, dated, where the work keeps them.
- Never ask what the spec or the code answers. Answer him first, check the premise
  after. Asked again for what you failed to deliver, say you failed, answer, offer the hand-over
  to a fresh session.
