# Rotation

## Context rotation

The module says when a gate trips; this is what you do then. It also tells the agent itself, which cannot read its own figure, but that line does not stand it down: send the stand-down below at once, never leave it to the brief's gate line. It says the same when a newer version of the plugins is installed: hand over at the end of the step in progress, at once when a defect of the running version blocks you.

Rotation = a **resume brief** (`agent-rotation-brief.md`) for a fresh session, written by the agent you stand down, which holds the state: your stand-down message names the template, the path to write and the tier line, and its acknowledgment answers that path. You neither read nor retype it: the launcher lints it. Below the threshold, prefer REUSING the same agent session across phases: it keeps the interfaces it built in mind and a continuation prompt costs a fraction of a cold start — « reuse » names an agent with a NEXT phase to start now; a tab kept in case is a forbidden standing-by tab. The same rule applies to you: hand over with a resume brief before degrading, with the traps this session paid for, not only the state.

**Execute the rotation yourself where the platform allows** (macOS + iTerm2): once the dispatch gate trips and the agent answered its resume brief's path, use the `orchestrator:iterm-agents` skill, « Safety order for a live rotation »: stand the old agent down and wait for its acknowledgment, `rotate --right-of self`, its lines the proof. Without such tooling, stop and say why.

## An agent the host stopped

`[module] <agent> stopped: usage limit (resets …)` or `stopped: API error …` means the host ended the agent's turn itself: it sits idle and answers nothing until the reset, whatever it had running. Do not wait on its reply: rotate it onto a fresh session from its pushed branch, on another tier when the limit is a model's (`You've hit your Opus limit`), its resume brief written by you from the branch, the pull request and the dispatch record, since it cannot write one. An API error that leaves its tab answering: send it one prompt to resume first.

## Your own context (the orchestrator is not exempt)

- SKILL.md's principles: 10 stay compaction-ready, 4 refresh the state from the artifacts, 7 measure your own context.
- **Keep your turn light**: a repository measurement, or a large file you need only a conclusion from, goes to a read-only subagent that returns it. A CI wait is one background `ci-watch.sh` per pull request, reporting its terminal state, never polled output; a long list or log is filtered to what the decision needs.
- **When your own session lacks what the role needs** — a PATH, a credential, a tool the launch did not carry — the repair is a successor spawned with it, never a favour asked of a peer or the operator.
